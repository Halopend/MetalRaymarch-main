# Threshold UI Audit — 2026-07-12

Branch: `thrsh/ui-audit-overhaul`

## Scope and method

This audit covered the macOS render workspace, the shared SwiftUI control
surface, iPad inspector behavior, visionOS-specific controls, animation
authoring, scene discovery, saving, keyboard navigation, accessibility, and
cross-platform build/test coverage.

Evidence came from:

- A source-level route and workflow inventory across `Threshold/App`,
  `Threshold/Views`, and `Threshold/Animation`.
- An interactive audit of a fresh `ThresholdMac` Debug build, including the
  collapsed render workspace and expanded control panel.
- Accessibility-tree inspection of the primary navigation and scene library.
- Generic-device builds for shared UI code and the existing Swift Testing suite.

## Product model observed

Threshold has a strong set of creative capabilities, but its UI previously
made the control surface harder to discover than the features themselves. On
macOS the initial view exposed only a small icon over the renderer. Once open,
the panel had five top-level workspaces, up to seven secondary sections, legacy
sub-routes, long-press-only pinning, and several separate utility windows.

The audit therefore prioritized wayfinding, safe recovery, reachable creation
flows, and compact layouts over adding more visual effects or decorative chrome.

## Changes in this pass

### Wayfinding

- Added a catalog-backed Control Finder with ranked title, path, description,
  and synonym search.
- Added direct routes for Explore, Shape, Visualizations, Performance, Music,
  Settings sections, Quick Toggles, and Animation Editor.
- Added Command-K to the macOS Navigate menu. It works while the control panel
  is hidden and pins the selected destination open.
- Made pinning explicit and filtered platform-inapplicable Shape > Hands routes
  from Mac/iPad navigation.

### Creation and recovery

- Registered the Animation Editor window on macOS and added an iPad
  presentation path.
- Rebuilt the editor workspace around a scene sidebar plus editor detail so an
  empty library can create its first scene without leaving the window.
- Changed the bottom action from an ambiguous green plus to a labeled Save
  control.
- Reordered save destinations around the common preset workflow and added a
  destructive confirmation before replacing the reset point.

### Responsive behavior

- Narrow iPad control inspectors use a horizontally scrolling section strip
  instead of a persistent 208-point rail.
- Compact iPad mode removes the meaningless disabled Detach action and keeps
  Record, Reset, and Save reachable.
- Scene, formula, gradient, preset, and color-mapping grids now adapt their
  column counts to available width.
- Scene cards can grow vertically for larger text.

### Accessibility

- Shared effect sliders expose value adjustment separately from enable/disable.
- Shared rows reflow at accessibility Dynamic Type sizes and no longer enforce
  a clipping-prone fixed height.
- Gradient preview interaction is a real Button with an explicit label/hint.
- Visible Save, Reset, Controls, pin, and pinned shortcuts meet a 44-point
  minimum on the shared surfaces touched in this pass.
- Flashing warnings respect Reduce Motion.

## Recommended next phase

These are high-value but require deeper product/state work than this UI pass:

1. **Undo/redo and dirty state.** Register parameter adjustments at the existing
   `MenuAdjustmentActions` begin/end boundary, treat scene loads as single
   transactions, and show whether the current state differs from its source.
2. **Preset lifecycle.** Add search/sort/favorites plus Rename, Update from
   Current, Duplicate, Export, and confirmed Delete. The manager already has
   deletion primitives, but the scene cards expose no management UI.
3. **In-app import.** Add File > Open on Mac and a document picker in Explore /
   Settings, routing into the existing external-file preview/confirm pipeline.
4. **Real image capture.** Expose the renderer's screenshot handler as Capture
   Image and use real captures for preset thumbnails.
5. **Actionable diagnostics.** Expose recent error history and add Retry / Open
   Settings / Show Details actions for recoverable failures.
6. **One route source of truth.** Replace synchronized dock, rail, legacy tab,
   and nested sub-tab storage with one typed route reducer. The Control Finder
   catalog is a useful first boundary for this migration.
7. **Automated UI coverage.** Add an XCUITest target and width/accessibility
   matrix. Current unit coverage now validates the finder catalog, but not the
   rendered compact shell or cross-window authoring flow.
8. **Deferred cross-platform quick-input system.** After transform controls are
   exposed through the shared Quick Controls model, add an iPad large-target
   Touch Deck with a hero slider; a world-stable visionOS radial menu using
   60-point-or-larger gaze, pinch, and direct-interaction targets; prioritized
   hand/input ownership with handedness fallback; and versioned Steam Input-style
   device bindings layered by fractal type. All presentations should bind stable
   semantic action and parameter IDs rather than platform-specific closures.

## Verification matrix

Completed on 2026-07-12: the macOS, iOS/iPadOS, and visionOS builds succeeded;
the serial macOS test run passed all 119 tests in 23 suites; and
`git diff --check` reported no patch-format errors. Existing compiler warnings
in the Metal and Quick Look targets remain outside this UI pass.

Required final gates for this shared UI branch:

```sh
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer Scripts/build.sh mac
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer Scripts/build.sh ios
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer Scripts/build.sh vision
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer Scripts/build.sh test
```

Manual acceptance checks:

- Mac launch: Controls is labeled; Command-K opens Finder while the panel is
  closed; selecting a result opens and pins the correct route.
- Save: no option is selected initially; preset naming is required; reset-point
  replacement requires confirmation; success feedback appears.
- Animation: editor opens from the rail and empty Animated state; scenes can be
  selected/created in its sidebar; the window is independently resizable.
- iPad: portrait and split inspector widths keep navigation and bottom actions
  reachable; top navigation scrolls; grids adapt without horizontal clipping.
- Accessibility: VoiceOver reaches slider and enable toggle independently;
  pin/unpin and scene edit named actions are announced; Reduce Motion stops the
  warning pulse.

`Scripts/build.sh all` now runs the generated-embed gate, macOS build, iPadOS-only
iOS target, visionOS build, and clean serial Mac test suite. Hardware interaction,
accessibility, and frame-time baselines still require the manual matrix above.
